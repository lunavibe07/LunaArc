# Password recovery and encrypted vault

Date: 2026-10-15, Asia/Bangkok.

## Request and behavior

Integrate the proposed password-list unlocker, mask recovery, encrypted vault and password verification into LunaArc. Version 1.2.0 adds Tools > Recover password, a real modal view with archive selection, list/mask search, progress, pause/resume/cancel, hidden/revealable results and opening the verified archive. Recovered secrets are scoped to the opened archive session and are not reused for archive creation.

## Implementation and design corrections

- Core PasswordRecovery lazily generates masks, escapes literal characters, bounds work to one million candidates, uses at most two workers, cancels remaining work after a verified match and preserves user cancellation. Catalog metadata limits are 10,000 entries and 256 MiB of declared output, summed without overflow.
- ReadCatalog alone is insufficient for content-encrypted ZIP/RAR. Candidates are verified using archive integrity tests. Standard tests now use SharpCompress checksum validation and discard output through VerificationWriteStream, enforcing pause/cancel and declared lengths.
- ZipAesIntegrity verifies WinZip AES password checks and HMAC-SHA1 authentication over ciphertext before testing or extracting. AE-2 skips the absent CRC only after authentication passes. This fixes correct AES ZIP passwords being rejected by the old unconditional CRC check. Encrypted ZIP64 and split ZIP are explicitly unsupported by this additional validator.
- PasswordVault replaces unused plaintext-JSON persistence with a versioned AES-256-GCM envelope, fresh salt/nonce, PBKDF2-SHA256 (600,000 iterations), authenticated data, master verification before replacing an existing vault and atomic temporary-file replacement. Linux vault creation uses owner-only permissions. UI clears master input after operations and all secret fields when the dialog closes.
- The proposed eight-byte tag is not inserted into existing LARC files. Its layout is incompatible with the current salt/IV/ciphertext envelope, and a quick tag alone cannot verify archive integrity. Existing LARC format and ciphertext remain unchanged.
- New recovery views/ViewModel, MainWindow integration, archive-session password handling, version metadata, README and AGENT guidance are updated in English.
- Synthetic ZIP/7z fixtures are independently generated by 7-Zip 25.01. RAR/RAR5 fixtures come from SharpCompress 0.50.5 with its MIT notice. They are test-only and no archived executables are launched.

## Limits and release status

Recovery is a bounded search, not a universal decryption algorithm. No GPU acceleration, persisted checkpoints or legacy plaintext-vault import is implemented. Pause applies between candidate attempts. LARC testing uses disposable temporary extraction and its existing whole-file buffering; metadata bounds are not comprehensive archive-bomb protection. Managed secret strings cannot be guaranteed to be erased immediately. Legacy password_vault.json is preserved and not read automatically.

Self-contained Windows publish succeeded at dist/win-x64; its CLI help runs successfully. Native Linux verification and Windows installer/portable packaging are delegated to the repository's CI workflow after source upload. No real local shell registration or installer lifecycle mutation is used.
